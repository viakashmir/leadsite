# TDI Holiday Ventures vs TavelPackage: depth audit (2026-11-13)

Follow-up to `tdiholidayventures.md` (2026-11-10). Goal set by the owner: beat
tdiholidayventures.com on every page that competes with it, every page at
1,600+ words, SEO/AEO/GEO-ready copy, and a clean UI in our own design (not
theirs).

How it was measured: every URL in both sitemaps was fetched and the visible
words inside `<main>` were counted (nav, header, footer, scripts excluded).
Ours were measured on a local production build of main (the live site
returns 402 while the Vercel block lasts), against a database seeded from
code, so admin-only edits on prod are not counted.

## Missing images

Photos live in the database (MediaAsset, served at /media/{slug}.webp). A
card or hero uses the package's own photo, else its city's, else its
destination's (lib/media.ts). When all three are empty, a card shows a
coloured gradient with the place name, and a blog or package hero shows
nothing.

`scripts/check-images.ts` checks every sitemap page for:

1. image sources that do not load (/media files, the source behind each
   /_next/image URL, og:image, JSON-LD image), each fetched once, so a run
   does not use Vercel's image-optimisation allowance;
2. pages with no photo at all inside `<main>`;
3. photo slots showing the gradient placeholder.

It cannot be answered from a local build: the local database is seeded from
code and has 2 photos, while the live database has the real library. Run it
against the live site as soon as the Vercel block lifts:

    npx tsx scripts/check-images.ts

Then fill each gap with a real, hand-checked photo of that exact place,
stored once as WebP in MediaAsset (lib/media.ts storeImageAsWebp) with its
own alt text.

## The other 1,700 pages: what 1,600 words everywhere would take

About 1,700 pages are under 1,600 words, and most are template pages. Adding
about 1,000 to 1,300 words each is roughly 1.5 to 2 million words. Done
honestly that is many batches over weeks. Done by padding templates with the
same paragraphs and the place name swapped in, it falls under Google's
scaled content abuse policy and would hurt the whole domain, so we will not
do that.

Recommended order (each batch: write, gate, local build, measure, push):

1. Package pages (97, all Kashmir): expand each itinerary day from one line
   to a real paragraph (drive time, what to see, what is optional, where you
   sleep), plus inclusions, exclusions, best months and FAQs. Biggest
   head-to-head gap against TDI's 60 packages (median 2,305 words).
2. The remaining Kashmir and Ladakh pages under 1,600 (about 280: city
   guides, places, how-to-reach, package hubs), so the whole TDI battleground
   clears the bar.
3. Blog posts under 1,600 in other states (about 270), via ADDITION batches
   per destination, the same way Kashmir was done.
4. City and state guides for the rest of India (about 270), written from
   facts per city.
5. Duration pages (401, median 336 words): give each one its own day-by-day
   itinerary written for that length. Where a destination has no real
   itinerary for a length, drop that length from the sitemap rather than
   pad it.
6. How-to-reach and places-to-visit pages for the rest of India.

Also open: 42 older blog posts in other states fail the existing 900-word
blog gate (`scripts/check-blog-quality.ts --list`).
